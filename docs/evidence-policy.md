# Release evidence and DoneClaim policy

`.omo/evidence/` is run-local release evidence. It is intentionally not a source
artifact: agents may create, replace, and delete files there while proving a
local run, but release policy must explicitly name any evidence that should be
promoted into committed documentation.

## File layout

Task evidence uses this shape:

```text
.omo/evidence/task-<N>-<slug>.<ext>
```

- `<N>` is the plan task number without leading zeroes, for example `6`.
- `<slug>` is lowercase ASCII words separated by hyphens: `evidence-policy`.
- `<ext>` is one of `txt`, `log`, `md`, or `json`.

Final audit evidence uses this shape:

```text
.omo/evidence/final-<slug>.<ext>
```

Use task evidence for RED, GREEN, negative-fixture, and QA command output. Use
final audit evidence only for whole-release summaries after all task evidence is
available. The one named exception is `.omo/evidence/release-candidate-summary.md`,
which is generated by the release-candidate rehearsal script and links the task
and final evidence set. Non-evidence fixture/source files may live temporarily
in the run-local directory, but the policy checker ignores extensions outside
the evidence set above rather than treating them as release evidence.

## DoneClaim metadata

Generated release evidence that claims a task or gate is done must include a
`DoneClaim:` block with these metadata headers before the command output:

```text
DoneClaim:
command: python3 scripts/release/check_evidence_policy.py .omo/evidence
cwd: /absolute/path/to/repo
timestamp: 2026-06-10T21:34:24Z
exit_code: 0
commit: 741b502
toolchain: python 3.14.4; zig 0.16.0-dev
stale_state: rejected
artifact_digest: sha256:<hex-digest>
```

Required fields are `command`, `cwd`, `timestamp`, `exit_code`, `commit`,
`toolchain`, and `stale_state`. `artifact_digest` is required when the evidence
claims a generated artifact, copied release file, archive, package, model output,
or any other durable artifact. It may be omitted for pure diagnostic logs.

`stale_state` records how the command rejected stale proof. Use `rejected` when
the command checked the current worktree, commit, timestamps, toolchain, or
artifact digest before accepting the claim. Use `not_applicable` only for RED
bootstrap evidence that proves a checker or target did not exist yet.

## Stale-state rejection

A DoneClaim is invalid when it cannot be tied to the current repository state.
Release checkers must reject evidence when:

- the command is missing or differs from the command being claimed;
- `cwd` is missing or is not the repository path used for the run;
- `timestamp` is missing or not an ISO-8601 UTC timestamp;
- `exit_code` is missing or not an integer;
- `commit` is missing or is not a 7- to 40-character hexadecimal Git SHA;
- `toolchain` is missing;
- `artifact_digest` is missing for an artifact-producing claim;
- stale-state handling is missing or does not explicitly say `rejected` or
  `not_applicable`.

Early bootstrap may have an empty or missing `.omo/evidence/` directory. That is
allowed only when the checker explicitly reports bootstrap mode. Once
`.omo/evidence/task-1-baseline.txt` exists, the evidence policy checker must
validate that T1 baseline evidence names the default release commands and records
command, cwd, toolchain, and exit-code metadata.
